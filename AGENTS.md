# Стиль кода и работа с проектом

Пользователь попросил изучить его код и запомнить стиль. Эти заметки составлены
по исходникам Client/, Server/ и CMakeLists.txt 28 сентября 2026 года.
Применять их при дальнейшей работе в этом проекте; явные пожелания пользователя
имеют приоритет. Проект небольшой, часть кода похожа на шаблоны Qt Creator:
не считать каждую встреченную конструкцию устойчивым личным предпочтением.

## Контекст проекта

- C++17, Qt Widgets и Qt Network; CMake собирает отдельные Client и Server.
- Интерфейс хранится в файлах .ui, окна — в MainWindowClient/MainWindowServer.
- Сетевая логика сервера вынесена в ConnectionServer, наследующий QObject.
- В текущей реализации сервер принимает UDP-сообщения и отправляет время клиенту.
- build/ содержит результаты сборки и сгенерированный код, а не образцы авторского стиля.

## Наблюдаемый стиль

- Отступы в C++ — четыре пробела. Скобка класса и функции на отдельной строке;
  открывающая скобка if/while — на строке условия. Короткие ветви бывают без скобок.
- Классы — PascalCase: ConnectionServer, MainWindowServer.
  Методы и переменные — lowerCamelCase: sendTime, readMessages, clientAddress.
- Поля без m_ и завершающего подчёркивания: socket, timer, connection, clientPort.
- Имена короткие, но отражают назначение; методы небольшие, логика прямая.
  Не вводить дополнительные слои и обобщения без практической необходимости.
- Объявления в .h, реализации в .cpp. Заголовки классов обычно названы строчными
  буквами; точки входа — mainClient.cpp и mainServer.cpp.
- В серверных заголовках используется #pragma once; в клиентском окне — include
  guards. При правках сохранять вариант файла; для новых аналогичных серверных
  классов ориентироваться на #pragma once.
- Используются предварительные объявления классов, когда полное определение
  в заголовке не требуется; соответствующие include размещаются в .cpp.
- Собственный заголовок стоит первым в реализации класса; связанные группы
  include и логические части метода разделяются пустыми строками.
- В классах приватные методы и поля могут быть разделены двумя секциями private:.
- Конструкторы с parent объявляются explicit, parent по умолчанию — nullptr.
- Объекты QObject создаются с родителем, например new QUdpSocket(this).
  Сохранять модель владения Qt; ui освобождается в деструкторе окна.
- Используется типизированный connect с указателями на методы, сигналы вызываются
  через emit. Обработчики могут быть обычными private-методами.
- Применяются типы и методы Qt: QString, QTime, QHostAddress, quint16,
  toString(), toUtf8(). auto используется точечно, когда тип очевиден;
  явные типы и const также встречаются.
- Простые значения полей могут инициализироваться прямо в объявлении
  (clientPort = 0); объекты — в списке инициализации либо конструкторе.
- Для некорректного пакета используется ранний continue. Сообщения диагностики
  выводятся через qDebug(). Тексты интерфейса и отдельные пояснения — по-русски,
  идентификаторы — по-английски. Комментариев немного.

## Как применять

- При локальных правках следовать ближайшему коду и сохранять компактность.
- Пробелы после if, положение * в указателях и оформление списков инициализации
  неоднородны. Не приписывать пользователю строгого правила и не переформатировать
  весь файл ради унификации.
- Сохранять существующее разделение интерфейса и сетевой логики, когда это
  соответствует задаче; новые сущности называть по аналогии с существующими.
- Не превращать незавершённые методы, возможные ошибки, строки протокола,
  номера портов или отсутствие проверок в правила кодестайла.
- Уточнять эти заметки по новым примерам и прямым указаниям пользователя.
